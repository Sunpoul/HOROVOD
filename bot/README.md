## Вариант 1: без сервера (только BotFather)

Подходит, если достаточно экрана перед запуском: Telegram показывает картинку, описание и свою кнопку **START**, а Mini App открывается кнопкой меню рядом с полем ввода.

1. `/mybots` → ваш бот → **Edit Bot** → **Edit Description**: вставьте описание из таблицы.
2. **Edit Bot** → **Edit About**: вставьте строку «О боте».
3. **Edit Bot** → **Edit Description Picture**: отправьте `description-640x360.png`.
4. **Edit Bot** → **Edit Botpic**: отправьте `avatar-640.png`.
5. **Bot Settings** → **Menu Button** → **Configure menu button**: адрес `https://sunpoul.github.io/HOROVOD/`, название `HOROVOD`.

Сообщения с кнопкой «Начать» после нажатия START в этом варианте не будет: боту нечем отвечать, пока он не запущен.

## Вариант 2: бот присылает приветственный пост с кнопкой «Начать»

Скрипт `horovod-bot.mjs` без зависимостей (нужен Node 18 или новее). Он отвечает на /start (так бот открывается впервые) приветственным постом с кнопкой «Начать», на остальные сообщения коротким напоминанием с той же кнопкой. При запуске он сам задаёт команды, описание, строку «О боте» и кнопку меню (картинку над описанием и аватар придётся поставить в BotFather, как в варианте 1).

```bash
node bot/horovod-bot.mjs
```

- Токен можно положить в файл, чтобы не вводить его и не показывать на экране: скопируйте токен в буфер обмена и выполните `pbpaste > bot/.token && chmod 600 bot/.token` (файл не попадает в git).
- Скрипт сам спросит токен из @BotFather: вставьте его в терминал и нажмите Return (символы не показываются). Запускать нужно в окне терминала, а не в строке ввода чата.
- Токен вводите только в своём терминале и никому не отправляйте. Скрипт не сохраняет и не печатает его. Если запускаете без терминала (сервер, `pm2`), задайте его заранее: `BOT_TOKEN=... node bot/horovod-bot.mjs`.
- Бот работает, пока запущен скрипт. Чтобы он отвечал всегда, запустите его на сервере или на компьютере, который не выключается (например, через `pm2` или `launchd`).
- Если адрес Mini App изменится, задайте `APP_URL=https://...` при запуске.
- Скрипт проверен на подставном API Telegram: на `/start` уходит картинка с подписью и кнопкой, повторные ответы используют уже загруженный файл, групповые чаты игнорируются. С настоящим Telegram и вашим токеном его нужно один раз запустить самому.

## Отправка из редактора: «Отправить в Telegram»

Редактор может сам отправить готовый ролик или кружок в чат с ботом. Telegram не даёт Mini App отправлять файлы от своего имени, поэтому нужен сервер: тот же `horovod-bot.mjs` принимает файл, проверяет подпись Telegram (`initData`) и вызывает `sendVideoNote` (кружок) или `sendVideo` для человека, который открыл редактор.

1. Запустите бота на машине с публичным HTTPS-адресом (сервер, либо туннель вроде Cloudflare Tunnel или ngrok на порт `8787`). Порт меняется через `PORT=...`.
2. Впишите этот адрес в `SEND_URL` в `src/app.src.html` (строка рядом с `NOTE_SIZE`), выполните `python3 build.py` и закоммитьте. Для проверки без пересборки адрес можно положить в `localStorage['horovod.send']`.
3. Если редактор открыт на другом сайте, добавьте его в `ALLOW_ORIGINS` (по умолчанию `https://horovod.su` и `https://sunpoul.github.io`).

Что проверяет бот: подпись `initData` токеном бота, возраст данных (не старше суток), сайт, откуда пришёл запрос, размер файла (до 50 МБ). Файл уходит только тому, кто открыл Mini App. Человек должен хотя бы раз нажать START у бота, иначе бот не сможет ему писать (редактор подскажет).

## Пост с кнопкой в канал

`bot/post-channel.mjs` публикует в канал картинку с описанием и кнопкой «Открыть HOROVOD». Кнопка ведёт на `https://t.me/gethorovod_bot?startapp` и открывает Mini App (кнопка `web_app` в каналах не работает, поэтому обычная ссылка).

1. В @BotFather один раз включите Main Mini App: `/mybots` → бот → Bot Settings → Configure Mini App → адрес `https://horovod.su/app.html`.
2. Добавьте бота в канал администратором с правом «Публикация сообщений» (для закрепа ещё «Закрепление сообщений»).
3. Запустите, например на сервере, где уже лежит токен: `cd /opt/horovod/app && node bot/post-channel.mjs @hrvd_chanel --pin`. Перед этим выполните `horovod-update`, чтобы скрипт появился на сервере.
4. Для проверки без отправки добавьте `--dry`. Свой текст — `--text "…"` (HTML), надпись кнопки — `--button "…"`, без картинки — `--no-photo`.

Токен берётся из `BOT_TOKEN` или файла `bot/.token`, скрипт его не печатает и не сохраняет.

## Новости об обновлениях

Каждая версия приложения получает новость в боте. Источник один — `bot/news.json`: новая версия добавляется **в начало** списка `releases`.

```json
{ "version": "1.3.1", "date": "2026-11-02", "title": "Понятная навигация",
  "done":  ["Что появилось — так, как это заметит человек"],
  "fixed": ["Что перестало ломаться"] }
```

- `/news` — бот присылает последнюю запись: «Что нового», «Исправлено» и кнопку «Открыть».
- Рассылка: при запуске бот сравнивает последнюю версию с уже разосланной (`bot/.state.json`) и, если она новая, один раз отправляет новость всем, кто ему писал (`bot/.subscribers.json`). Скорость — около 20 сообщений в секунду, кто заблокировал бота, удаляется из списка. Оба файла в git не попадают.
- Выпустить новость: `git pull`, затем перезапустить бота. Чтобы перезапустить без рассылки: `ANNOUNCE=0 node bot/horovod-bot.mjs`.
- Список подписчиков начинает копиться с этой версии бота: те, кто писал боту раньше, получат новости после любого следующего сообщения боту (или `/start`).
- Проверено на подставном API Telegram: рассылка уходит один раз, повторный запуск ничего не шлёт, заблокировавшие удаляются, тот, кто сам спросил `/news` во время рассылки, второй копии не получает.

## Сервер

Бот работает на VPS в Амстердаме (Ubuntu, служба `horovod-bot`, HTTPS через Caddy на `https://api.horovod.su`). Сервер настроен скриптом cloud-init: Node.js, Caddy, код в `/opt/horovod/app`, токен в `/opt/horovod/app/bot/.token`.

- Обновить бота и разослать новость новой версии: `ssh root@186.246.113.84`, затем `horovod-update`.
- Журнал: `journalctl -u horovod-bot -n 50 --no-pager`. Статус: `systemctl status horovod-bot`.
- Бот на Mac больше не запускать: две копии с одним токеном мешают друг другу.

## Поддержка

Куда приходят сообщения о проблемах:
- **из приложения** — экран «Поддержка» → «Нашли ошибку?»: текст и данные об устройстве (`POST /support`, подпись Telegram проверяется, не чаще раза в 15 секунд);
- **из чата** — любое сообщение боту, кроме команд (текст, скриншот, запись экрана), пересылается как есть; человек получает ответ «Спасибо, передал разработчику». `/support` и ссылка `t.me/gethorovod_bot?start=support` просят описать проблему.

Сообщения получают разработчики из файла `bot/.admins` (id по одному в строке, в git не попадает). Подключиться: отправить боту `/admin` — он пришлёт свой id и команду, которую нужно выполнить на сервере (`echo <id> >> /opt/horovod/app/bot/.admins`); перезапуск не нужен. Ответить человеку — ответить реплаем на сообщение «Поддержка» или на пересланное сообщение: бот скопирует ответ в чат человека. Пока `.admins` пуст, сообщения складываются в `bot/.inbox.jsonl`.
